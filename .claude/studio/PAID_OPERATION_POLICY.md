# Paid Operation Policy

Paid provider work is a human-controlled production action.

Before the first paid call in a job, the Studio Lead must state:

- provider and operation;
- asset(s) being produced or edited;
- planned number of calls/frames/directions;
- expected cost in the provider's native units when available;
- retry/attempt cap;
- fallback if the cap is reached;
- what will be preserved in the generation record.

The job stops until Raheem or an approved studio operator authorizes the plan, unless an already-approved bounded budget explicitly covers it.

Each paid result records prompt, negative prompt where applicable, provider/model/operation, seed/job ID when available, references, output path, actual cost, validator result, runtime review result, and human approval status.

Do not pay a generative model to perform a deterministic correction that an existing local tool can safely perform.
