# Skill Lifecycle Contract

Every active studio skill must make these items discoverable without inference:

1. **TRIGGER** — the situation that activates the workflow.
2. **EXCLUSIONS** — situations that must use another workflow or direct implementation.
3. **INPUTS** — exact information or artifacts required.
4. **PREFLIGHT** — canonical sources, clean-state checks, dependencies, and stop conditions.
5. **WORKFLOW** — ordered, executable steps.
6. **APPROVAL GATES** — economy, paid services, destructive actions, push/PR/deploy, or subjective visuals.
7. **VERIFICATION** — deterministic checks plus runtime/visual evidence when the work has a game surface.
8. **OUTPUTS** — files, branch, evidence, or inline proposal produced.
9. **HARVEST REVIEW** — whether the task revealed a reusable component, fixture, rule, skill change, or document update.

A skill is not allowed to silently bypass a missing precondition. Inactive scaffolds and completed one-time migrations must not remain model-invocable.
